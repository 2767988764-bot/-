# 仓储物流管理系统（WMS）开发推进清单

> 目标：把当前「前端 + mock 演示」推进到「前后端联调 → 安全上线」的可交付版本。
> 当前状态：前端已完成（Vue2 + Element UI，20+ 视图，全 mock 数据），后端尚未搭建。

---

## 第 0 步：先做技术决策（动手写代码前必须先定，否则返工）

| # | 决策项 | 推荐方案 | 备选 | 决策人 |
|---|---|---|---|---|
| 1 | 后端语言/框架 | 若你偏 Python：**FastAPI + SQLAlchemy + Pydantic**（快速、自带接口文档、类型安全） | 若团队惯用 Java：Spring Boot + MyBatis | 你 |
| 2 | 数据库 | **PostgreSQL**（WMS 多表关联、报表强项） | MySQL 亦可，**不建议 SQLite 上生产** | 你 |
| 3 | 认证方案 | **JWT（Access 短过期 + Refresh 刷新）**，密码 bcrypt 加盐哈希 | 可先做单 Token 简化 | 你 |
| 4 | 部署形态 | 单台云服务器：后端进程 + PostgreSQL + Nginx 反代 `/api` | Docker Compose（后端 + 数据库容器化） | 你 |
| 5 | 前端交付 | 已可 `npm run build` 出静态包 → 由 Nginx 托管 | 已有 GitHub Pages demo 可继续用 | 你 |

> 决策建议：你的技术栈以 Python 为核心，**FastAPI + PostgreSQL + Nginx** 是最平滑、最快出活的组合。下面所有任务按此组合描述，换框架只影响「实现」，不影响「步骤与验收」。

## 后端安全 Checklist（逐项打勾）

**认证与鉴权**
- [ ] 密码一律 bcrypt 加盐哈希，数据库无明文
- [ ] 登录返回真实 JWT，短过期 + Refresh 刷新
- [ ] 每个受保护接口都校验 token（不只是登录接口）
- [ ] 每个接口做角色/权限校验（不只靠前端隐藏菜单）
- [ ] 登出 / 改密后 token 能失效（黑名单或短过期兜底）

**输入与输出**
- [ ] 所有 SQL 参数化查询，无字符串拼接
- [ ] 输出转义，防 XSS；表单校验服务端重复做
- [ ] 防 CSRF（校验来源/Token 策略）
- [ ] 接口限流 + 登录失败锁定
- [ ] 敏感字段（手机号、邮箱）列表展示脱敏

**数据存储**
- [ ] 数据库不暴露公网，仅内网/后端访问
- [ ] 业务账号最小权限，不用 root 连库
- [ ] 强密码 + 定期轮换
- [ ] 关键商业字段按需加密存储

**审计与备份**
- [ ] 关键写操作记审计日志（谁、何时、改了什么）
- [ ] 定期自动备份（全量 + 增量）
- [ ] 3-2-1 备份（3 副本 / 2 介质 / 1 异地）
- [ ] 定期恢复演练，备份可真正还原

**运维**
- [ ] 服务器只开必要端口，系统及时打补丁
- [ ] 账号最小权限，离职即回收
- [ ] 敏感配置（密钥、数据库密码）不入代码库，走环境变量
